## Bootstrap, review, reserve, apply

1. Copy `infra/bootstrap/terraform.tfvars.example` to ignored `terraform.tfvars`. Supply subscription, globally unique storage name, current operator object/principal UUID, actual public IPv4 `/32` (converted to a bare address for Storage ACL) or `/1`–`/30` CIDR, UTC TTL and conservative hourly estimate. The example's documentation IP is not usable. Ensure current outbound address reaches the endpoint; Azure ACLs reject private addresses and `/31`. Do not open `0.0.0.0/0` to solve reachability.
2. Bootstrap initially uses **local state**. `make -C infra/bootstrap plan` creates ignored `reviewed.tfplan`. Review `terraform -chdir=infra/bootstrap show reviewed.tfplan`; only four resources (RG, state account, operator Blob role, private container; verify actual plan) in this project are allowed. There is no paid tenant-global app registration. Keep local state on encrypted disk with permissions restricted to the operator.
3. Refresh both price captures using `scripts/azure_budget.py capture`. Prepare ignored `infra/bootstrap/proposal.json` matching each changed resource address. `docs/dev/azure-proposal.example.json` shows one priced storage record; include zero-cost ARM resources individually with empty meters, same bounded start/end, region/type and estimate 0. The guard obtains JSON from the actual binary plan itself, not a caller-supplied JSON, and allows only Task 1 create types. Updates, replacements and deletes require separate review and are refused by this admission path.
4. `make -C infra/bootstrap reserve` validates prices/quantities/scope/tags, checks historical estimates + new ≤18 USD, and writes **every resource before creation** to the canonical local ledger `docs/dev/azure-ledger.json` (not in git), bound to binary plan SHA256. Review that journal. Saved binary plans remain ignored because they may contain sensitive state. A reservation is not evidence of creation. All reserve/check operations lock `docs/dev/azure-ledger.json.lock` across reading, admission and durable atomic journal replacement. Reconciliation writers must use the same `scripts.azure_budget.ledger_lock()` and `persist_ledger()` helpers; do not edit/replace the journal or remove its lock sidecar while tools run. A verified no-change plan with an empty resource proposal needs no new receipt and leaves the journal unchanged. Never remove reservations to recover headroom; retain conservative cancelled/failed estimates until reviewed reconciliation.
5. Only after review: `make up ENV=infra/bootstrap`. Both root and child Make apply routes run the fail-closed guard again and apply the exact saved plan. Do not use raw `terraform apply` to bypass controls. The first actual apply belongs to the controller after independent review.

Storage network ACL defaults to Deny, bypass None, only supplied operator IPv4 addresses allowed. Shared keys and anonymous blobs are disabled; Entra data-plane auth is configured. Storage account uses Standard_LRS, TLS1.2, seven-day blob/container soft-delete, versioning and seven-day change feed. A container child cannot carry Azure tags; parent account carries all four tags and its metered storage/requests (including versions, retained deletions and change feed) are included in the reservation. Role assignments and federated credential also do not support tags; their parent RG/identity owns expiry and their separate journal rows record that boundary.

RBAC is eventually consistent: `depends_on` orders the operator Blob assignment before container creation, but propagation can still take minutes. A failed create remains reserved, not free. Wait for assignment propagation, inspect actual state/resources, then produce a fresh reviewed plan and reconcile duplicate reservations conservatively. Do not enable account keys or widen the ACL. Operator RBAC must include Storage Blob Data Contributor; management-plane Owner/Contributor alone does not grant blob access. If the chosen container API uses ARM, migration still requires data-plane RBAC and network reachability.

```bash
source scripts/dev-env.sh
terraform -chdir=infra/bootstrap init -migrate-state -backend-config=backend.tfbackend

```

Review the migration prompt before copying. Do not combine `-reconfigure` with `-migrate-state`; do not leave state duplicates in an unencrypted location. Azure backend uses an Azure Blob lease for mutual exclusion; backend metadata persists between invocations, while a lease is held during operations, not forever. The controller has now verified real migration, Entra data-plane access and competing-process lease locking; see the cloud evidence above. Version restore remains untested. Test lock contention using two sessions against a disposable state key and record the expected lock error; mocks cannot prove remote locking. Avoid force-unlock unless the lock owner has been checked.
